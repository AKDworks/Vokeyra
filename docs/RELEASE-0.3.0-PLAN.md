# Подготовка Vokeyra 0.3.0

Целевой публичный выпуск — 0.3.0. Владелец разрешил отправку окончательных исправлений на GitHub и публикацию релиза. Профили приложений отложены.

## Порядок

1. Добавить и проверить пять моделей: Vosk Small Russian, Zipformer GigaSpeech English, Moonshine Base English, SenseVoice Small, Distil-Whisper Large v3. Сохранить максимум пять рекомендаций; веса скачиваются отдельно от установщика.
2. Подготовить Linux x64 в экспериментальном статусе, с `.deb` и `.AppImage`. По решению владельца для первого выпуска используются автоматические проверки на сервере GitHub без установки Linux на его ПК. Установка `.deb`, запуск обоих пакетов, запись с виртуального микрофона, распознавание, история и сохранение настроек прошли в [CI для коммита 8560e2c](https://github.com/AKDworks/Vokeyra/actions/runs/39040820359). Физические устройства, настоящий рабочий стол, нативный Wayland, трей, автозапуск и обновления остаются для последующего тестирования; ограничения указать в документации и релизе.
3. Подготовить проверяемую сборку из исходников в GitHub Actions и выпустить 0.3.0 без Windows Authenticode по решению владельца. Окончательный Windows-пакет проверен после распаковки установщика; установка поверх 0.1.1 остаётся непроверенной и отмечается в ограничениях релиза. Linux-пакеты перед публикацией пересобираются из окончательного кода и проходят автоматические проверки. Подпись Tauri updater и `latest.json` формировать для окончательных файлов. Подготовить английские release notes; коммит, отправка на GitHub и публикация разрешены владельцем.
4. После публикации 0.3.0 отправить заявку в SignPath Foundation. Черновик подготовлен отдельно от публичных файлов; отправка требует согласования владельца. Отсутствие Authenticode само по себе не запрещает выпуск. Сбой запуска отдельного .NET-модуля устранён переносом Windows-интеграции в режим собственного EXE Vokeyra. Приложение из пересобранного установщика прошло на этом ПК проверку горячих клавиш, реального микрофона, восстановления разрешения, распознавания и нативного ввода; настройки защиты не менялись. Установка поверх 0.1.1 ещё не проверена. Исправления включены в окончательную подготовку 0.3.0.
5. После одобрения SignPath настроить Windows Authenticode для собственных EXE и установщика в следующем выпуске. Подписать внутренние файлы до упаковки, установщик — после упаковки. Затем заново сформировать подпись Tauri updater и `latest.json`: последующее изменение файла нарушит проверку обновления. Уже опубликованные файлы 0.3.0 не заменять изменёнными файлами под теми же именами.

## Что потребуется для SignPath

- Публичный исходный код и уже доступный выпуск в распространяемом формате. По решению владельца заявка подаётся после публикации 0.3.0.
- Описание функций, правила подписи и политика конфиденциальности в репозитории; не заявлять о полученной подписи до фактического одобрения.
- Двухфакторная аутентификация и назначенный ответственный за одобрение каждой подписи.
- Воспроизводимый для проверки путь от исходников и зависимостей до артефактов CI. Сторонние бинарные компоненты учитываются отдельно от собственных файлов.

SignPath Foundation предоставляет бесплатную подпись подходящим открытым проектам, но принятие заявки не гарантируется. В качестве издателя сертификата выступает SignPath Foundation; автором Vokeyra остаётся AKDworks.

Windows Authenticode и подпись обновлений Tauri — разные механизмы. Действительная Authenticode-подпись сама по себе не гарантирует немедленного отсутствия предупреждений SmartScreen: Windows также учитывает репутацию файла и издателя.

Источники: [условия SignPath Foundation](https://signpath.org/terms.html), [SignPath Foundation](https://signpath.org/), [Microsoft: репутация SmartScreen](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).
