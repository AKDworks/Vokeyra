# Linux x64: подготовка и проверка

Vokeyra работает локально: запись идёт из микрофона, распознавание выполняет отдельная Node-служба, а результат либо вставляется в активное приложение, либо остаётся в истории. На Linux базовая запись, модели и история не зависят от интеграций с рабочим столом.

## Что проверено, а что подготовлено

| Область | Состояние |
| --- | --- |
| Ubuntu 22.04 x64, X11, `.deb` и `.AppImage` | Проверено в CI: синтетическая речь через PulseAudio, Whisper и запись в историю |
| Fedora 44 x64, RPM | Собрано и запущено в CI в X11; запись и распознавание требуют отдельной проверки |
| Windows | Общая логика WebView-записи проверена типизацией и юнит-тестами; ручная проверка Windows после изменений не выполнялась |
| Native Wayland: niri и KDE Plasma | Работа вручную проверена участником разработки; автоматическая проверка на реальном Wayland-композиторе не выполнялась |
| Индикатор layer-shell | Реализован нативным GTK/Cairo с runtime-проверкой; на системах без gtk-layer-shell используется компактное обычное окно |
| Масштабирование 100–200% | Логика размеров и отказ от принудительного software-rendering подготовлены; визуальная проверка на каждом масштабе остаётся ручной |

В CI используется виртуальный X11, поэтому он не доказывает поведение native Wayland, тайлинговых композиторов, portal-сервисов и дробного масштабирования.

## Быстрый старт на niri

1. Запустите Vokeyra и откройте вкладку **Главное → Linux**. Раздел показывает композитор, сеанс, доступность portal и четыре строки: горячая клавиша, удержание, вставка текста и индикатор.
2. Для запуска записи без portal и swhkd добавьте привязку в `~/.config/niri/config.kdl`:

```kdl
binds {
    Mod+Shift+Space { spawn "vokeyra" "--toggle"; }
}
```

3. Сохраните файл — niri перечитывает конфигурацию без перезапуска.
4. Проверьте `niri msg --json windows`: окно с заголовком `Vokeyra Indicator` не должно появляться среди тайлов. При активном layer-shell его там нет вовсе.
5. Если индикатор показан обычным окном, добавьте узкое правило только для него:

```kdl
window-rule {
    match title="^Vokeyra Indicator$"
    open-floating true
    default-column-width { fixed 248; }
    default-window-height { fixed 58; }
    open-focused false
}
```

Значения `248` и `58` — логические пиксели, как и размеры окна в Vokeyra. Правило не делает плавающим основное окно приложения. App-id зависит от сборки и темы; уточните его командой `niri msg pick-window`, выбрав индикатор. Локализованный заголовок больше не используется: окно индикатора всегда называется `Vokeyra Indicator`.

niri передаёт приложениям только нажатие клавиши. Поэтому на niri поддерживается переключение (`vokeyra --toggle`), но не удержание: `--press` без события отпускания оставил бы запись включённой. Строка «Удержание для записи» в этом случае честно показывает «Недоступно». Для удержания на niri нужен `swhkd`, который читает evdev и умеет привязку `@release`.

## Индикатор записи

Индикатор — отдельная нативная GTK-поверхность, нарисованная через Cairo, размером 248×58 логических пикселей. Основное окно Vokeyra остаётся обычным окном WebView.

На native Wayland Vokeyra при старте:

1. проверяет, что сеанс действительно Wayland;
2. загружает `libgtk-layer-shell.so.0` во время выполнения (жёсткой зависимости при сборке нет);
3. проверяет `gtk_layer_is_supported()`, то есть наличие протокола `zwlr_layer_shell_v1` у композитора;
4. до первого показа окна инициализирует layer-surface с namespace `vokeyra-indicator`, слоем overlay, `exclusive_zone = 0` и режимом клавиатуры `none`.

Это даёт:

- отсутствие участия в раскладке тайлинга и изменений размеров других окон;
- отсутствие резервирования рабочего места (это не панель);
- отсутствие клавиатурного фокуса у индикатора;
- кнопку отмены, которая работает мышью;
- позиционирование у верхнего или нижнего края выбранного монитора с учётом логического масштаба.

Индикатор не использует WebView: текст, скругления и шкала уровня рисуются Cairo на логических координатах, поэтому GTK сам выбирает целочисленный buffer scale, а прозрачность не зависит от WebKitGTK. Это устраняет мерцание прозрачной WebView-поверхности и размытие, которое давал программный рендеринг.

Если layer-shell или протокол недоступны, Vokeyra не ломает запись: создаётся компактное нативное окно с фиксированным размером (`248×58`), `accept_focus = false`, `focus_on_map = false`, `skipTaskbar`, `Utility`-подсказкой и transient-родителем. niri автоматически делает плавающими окна с родителем или фиксированным размером, поэтому fallback не превращается в тайл и на niri. Однако niri всё равно может сфокусировать новое обычное окно: в правиле ниже обязателен `open-focused false`. С layer-shell клавиатурного фокуса нет вообще. Заголовок `Vokeyra Indicator` стабилен и не переводится.

Индикатор скрывается при завершении распознавания, отмене, отключении наложения в настройках, ошибке службы распознавания и завершении приложения. Ошибка показа индикатора не прерывает запись: текст всё равно сохраняется в истории.

### Запись звука в Linux

На Linux микрофон захватывает служба распознавания через `parec` (PulseAudio / PipeWire), а не WebView. WebKitGTK приостанавливает `getUserMedia`, когда окно приложения скрыто, поэтому при запуске из трея или автозапуска запись по горячей клавише зависала на «Микрофон…». Теперь служба получает PCM напрямую, обновляет уровень и таймер индикатора и передаёт готовый WAV обычному пути распознавания. Это работает при скрытом основном окне.

Нужен `parec`: в Arch он входит в `libpulse`, в Debian/Ubuntu — в `pulseaudio-utils`; эти пакеты добавлены в зависимости Vokeyra. Если `parec` недоступен, приложение сообщает об ошибке и предлагает ручной сценарий, а не зависает.

В Linux список микрофонов в настройках теперь строится по именам источников PulseAudio/PipeWire, а не по непрозрачным device id WebView. Старые сохранённые id, которые не совпадают с текущими источниками, при запуске мигрируют на «По умолчанию»; остальные настройки и история сохраняются. Если выбранный источник исчез во время работы, Vokeyra продолжает запись с системного источника по умолчанию и явно сообщает об этом в уведомлении. Если fallback отключён, запись завершается понятной ошибкой, а не молчаливым выбором другого устройства.

Служба ограничивает запись пятью минутами независимо от отзывчивости интерфейса: лишние PCM-данные не сохраняются, процесс захвата останавливается, а автостоп срабатывает один раз. Неожиданное завершение `parec` после успешного старта не выдаётся за успешную запись: Vokeyra отменяет сессию, восстанавливает приглушённый звук и показывает причину. Ожидаемая остановка по кнопке или лимиту ошибкой не считается.

### Если индикатор выглядит как широкое окно с HTML-полосой

Это признак того, что запущена старая сборка со старым WebView-индикатором, а не нативный индикатор из этого дерева. Проверьте:

```sh
niri msg --json layers | grep vokeyra-indicator
```

При активном layer-shell команда должна показать namespace `vokeyra-indicator`. В логе приложения должна быть строка `Vokeyra overlay: native layer-shell indicator`. Если её нет, `vokeyra` в `$PATH` может указывать на давно установленный бинарник: пересоберите пакет или для проверки укажите в привязке niri полный путь к свежему бинарнику, например `/home/пользователь/Vokeyra/src-tauri/target/debug/vokeyra --toggle`.

Привязка `spawn-sh "vokeyra --toggle"` сама по себе не вызывает такой вид: она только передаёт `--toggle` уже запущенному экземпляру. Важно, какой именно бинарник запущен первым.

## Размытие и масштабирование

Раньше `WEBKIT_DISABLE_DMABUF_RENDERER=1` выставлялся для всех Linux-сеансов. Это обходной путь от пустого окна WebKitGTK в некоторых конфигурациях, но он заставляет WebKit рендерить через программный путь и на native Wayland может ухудшать чёткость основного окна. Теперь:

- на X11 переменная по-прежнему выставляется автоматически;
- на native Wayland WebKit использует обычный DMABUF-путь;
- принудительно вернуть старый обход можно переменной `VOKEYRA_DISABLE_DMABUF_RENDERER=1` (или явно задать `WEBKIT_DISABLE_DMABUF_RENDERER=1`);
- глобальные `GDK_SCALE`, `GDK_DPI_SCALE` и произвольный CSS `scale()` не используются.

Индикатор вообще не зависит от WebKit: его Cairo-поверхность масштабируется GTK вместе с layer-surface. Логические 248×58 не меняются, поэтому на 125%, 150% и 200% шкала и текст остаются резкими. Основное окно использует WebKitGTK; его дробное масштабирование по-прежнему зависит от версии GTK, WebKitGTK и композитора. При проблеме проверьте:

```sh
echo "XDG_SESSION_TYPE=$XDG_SESSION_TYPE WAYLAND_DISPLAY=$WAYLAND_DISPLAY GDK_BACKEND=$GDK_BACKEND"
niri msg --json outputs   # или настройки масштаба вашего композитора
```

Vokeyra сообщает фактический сеанс в разделе Linux. Запуск с `GDK_BACKEND=x11` означает XWayland, а не native Wayland, и может масштабировать поверхность иначе.

Ручная проверка обязательна на 100%, 125%, 150% и 200%: текст, скругления и индикатор уровня не должны быть размытыми, обрезанными или растянутыми на половину экрана. При переключении между мониторами с разным DPI индикатор должен оставаться на мониторе с курсором.

## Настройка Linux-интеграций

Раздел **Главное → Linux** не угадывает по одному факту установки пакета. Для каждой строки показывается одно из состояний:

- **Работает** — проверенный путь (например, X11 global-shortcut или подключённый swhkd);
- **Готово** — компонент найден, но Vokeyra не отправляет тестовые клавиши в активное окно;
- **Требуется настройка** — нужен бинг композитора, демон или разрешение;
- **Недоступно** — в этой сессии способ не поддерживается;
- **Ошибка** — backend перестал работать; текст остаётся в истории.

Кнопка **Проверить снова** заново ищет инструменты, проверяет сокет и процесс `ydotoold`, доступ к `/dev/uinput`, подключение swhkd и наличие интерфейса `org.freedesktop.portal.GlobalShortcuts`. Она не устанавливает пакеты, не меняет группы пользователя, не запускает `sudo` и не переписывает конфигурацию композитора.

Если интеграции недоступны, базовый сценарий остаётся рабочим: запись кнопкой на вкладке **История**, копирование результата, ручная вставка. Ручная запись на Linux открыта по умолчанию.

### Горячие клавиши

| Окружение | Рекомендуемый способ | Удержание |
| --- | --- | --- |
| niri | `vokeyra --toggle` в `binds` | Нет; только swhkd |
| Sway | `bindsym $mod+Shift+space exec vokeyra --toggle` | Да, отдельными `--release` привязками |
| Hyprland | `bind = SUPER SHIFT, SPACE, exec, vokeyra --toggle` | Да, `bind` + `bindr` |
| KDE Plasma | Пользовательская команда `vokeyra --toggle` в системных настройках | Нет; только swhkd |
| GNOME | Пользовательская команда в настройках клавиатуры | Нет; только swhkd |
| X11 | Глобальная клавиша Tauri | Да |

Флаги командной строки: `--toggle` (начать/остановить), `--press` (начало удержания), `--release` (окончание удержания), `--cancel` (отменить текущую запись). Автоповтор нажатия не запускает вторую запись: служба игнорирует повторный `--press` до `--release`. Если композитор умеет только toggle, Vokeyra не заявляет push-to-talk.

Sway и Hyprland поддерживают отдельные события отпускания, поэтому в их строке появляется настройка удержания. Для Sway используйте `bindsym --release`, для Hyprland — `bindr`. Проверяйте синтаксис по документации установленной версии композитора.

Наличие `swhkd` само по себе ничего не подключает. Vokeyra атомарно генерирует `~/.local/share/Vokeyra/swhkdrc` с привязками `--press` и `@release`; в существующий `~/.config/swhkd/swhkdrc` нужно один раз добавить строку `include /полный/путь/swhkdrc`. Кнопка **Открыть swhkdrc** показывает сгенерированный файл. Файл можно безопасно перегенерировать и удалить; Vokeyra не изменяет общий конфиг swhkd.

Портал `org.freedesktop.portal.GlobalShortcuts` проверяется отдельно. Наличие интерфейса в D-Bus означает, что backend portal его экспортирует, но не гарантирует, что текущая интеграция Vokeyra умеет запрашивать привязки. В этой версии Vokeyra не регистрирует через portal и использует привязку композитора; интерфейс показывается как диагностическая информация, чтобы не создавать ложного ощущения работающей клавиши. Это ограничение явно указано в строке «Горячая клавиша».

### Вставка текста

Порядок выбора на Wayland:

1. `wtype` — если найден. Протокол `zwp_virtual_keyboard` проверяется реальной вставкой, а не эмуляцией Shift в активном окне.
2. `ydotool` — только если найден и одновременно работают `ydotoold` и его сокет (`$YDOTOOL_SOCKET` или `$XDG_RUNTIME_DIR/.ydotool_socket`).
3. `dotool` — только при доступе к `/dev/uinput` и `/dev/input`.

На X11 используется `xdotool`. Текст передаётся через stdin или аргументы без shell-интерполяции.

Если backend перестал работать, Vokeyra помечает диагностику как ошибку. При неоднозначном результате (команда уже запускалась и могла частично ввести текст) повторная вставка через другой backend не выполняется — это защищает от двойного текста. Следующая запись попробует альтернативу, а кнопка **Проверить снова** сбросит сохранённую ошибку.

При работе через буфер Vokeyra запоминает прежнее текстовое содержимое, но восстанавливает его только если буфер всё ещё содержит распознанный текст. Если пользователь успел скопировать что-то новое, его данные не затираются. При сбое распознанный текст остаётся в истории и в поле «Последний текст».

Для `ydotool` нужен работающий `ydotoold` и доступ к его сокету, а не только установленный бинарник. Для `dotool` и `ydotool` права на `/dev/uinput` настраиваются средствами дистрибутива; Vokeyra не добавляет пользователя в группы.

### Отключение системного звука

Используется `wpctl` (PipeWire) или `pactl` (PulseAudio). Если звук уже был выключен, Vokeyra не включает его после записи. Если восстановление не удалось, попытка повторяется при завершении приложения.

## Сборка и пакеты

Проверочная сборка запускается при отправке разрешённых изменений в тестовую ветку `testing`. Workflow имеет доступ `contents: read`, не создаёт коммиты, теги или релизы. Результат — `.deb` и `.AppImage` без подписи обновлений.

Локально на Ubuntu 22.04 / Debian:

```sh
npm ci
npm run dist:linux:unsigned
```

Нужны Node.js 24.18.0, Rust и системные зависимости из [workflow](../.github/workflows/linux-build.yml). Для AppImage установите `xdotool`, `wl-clipboard` и компоненты GStreamer из репозитория дистрибутива. Не запускайте Vokeyra от root.

Пакеты находятся в `src-tauri/target/release/bundle/deb` и `.../appimage`. Служба Linux собирается в `dist/desktop-linux`.

`gtk-layer-shell` — runtime-зависимость индикатора. В пакетах Vokeyra она объявлена обязательной: `gtk-layer-shell` для Arch и RPM, `libgtk-layer-shell0` для `.deb`. Библиотека загружается динамически, поэтому приложение всё равно запустится, если пакета нет, и перейдёт на fallback-окно. Для отладки fallback можно выставить `VOKEYRA_DISABLE_LAYER_SHELL=1`.

### RPM

В 0.3.1 добавлен экспериментальный RPM x64 для Fedora. Проверка на реальном рабочем столе не проводилась. `npm run dist:linux` собирает `.deb`, `.AppImage` и `.rpm`; обновления используют цель `linux-x86_64-rpm`.

### Arch Linux

В `packaging/arch/` есть `PKGBUILD` (сборка из исходников) и `PKGBUILD.bin` (бинарный пакет из `.deb`). `gtk-layer-shell` входит в обязательные зависимости; опциональные: `wtype`, `ydotool`, `dotool`, `swhkd`.

```sh
cd packaging/arch
makepkg -si
```

## Проверка native Wayland / niri

Сначала запустите read-only проверку окружения:

```sh
npm run check:wayland
```

Скрипт печатает композитор, наличие layer-shell, portal, `wtype`, состояние `ydotoold`, доступ к `dotool` и найденный `swhkd`. Он не отправляет клавиши и ничего не устанавливает. Если запущен niri, он также покажет открытые окна `Vokeyra Indicator`.

Проверяйте сценарий в обычном сеансе niri, не меняя системный конфиг. Для экспериментов с привязками используйте отдельную копию `config.kdl` и `niri validate` перед применением.

1. Запустите Vokeyra; откройте **Главное → Linux** и нажмите **Проверить снова**.
2. Откройте любой текстовый редактор, поставьте курсор в поле и начните запись привязкой `vokeyra --toggle`.
3. Ожидаемо: пилюля 248×58 логических пикселей у выбранного края, не тайл, фокус остаётся в редакторе; ввод с клавиатуры продолжает доходить до редактора.
4. Нажмите кнопку отмены на пилюле. Ожидаемо: пилюля исчезла, текст не вставлен, история не получила новую запись.
5. Повторите запись и завершите её. Ожидаемо: текст вставлен ровно один раз; при недоступном backend текст доступен в истории и поле «Последний текст».
6. Повторите на 100%, 125%, 150% и 200% масштабе, затем на втором мониторе с другим DPI. Ожидаемо: пилюля не растягивается, текст и шкала читаемы.
7. Отключите `wtype` из PATH (или используйте тестовый профиль без него) и повторите вставку. Ожидаемо: раздел Linux объясняет причину, запись не ломается, результат можно скопировать вручную.

Проверка X11 в CI остаётся в `scripts/smoke-linux-ui.mjs` и намеренно не подменяет native Wayland.

## Дальнейшие проверки на реальном рабочем столе

- niri: layer-shell, фокус, кнопка отмены, размер и позиция на нескольких мониторах.
- KDE Plasma и GNOME: fallback-окно, portal-диагностика, привязки композитора.
- Sway и Hyprland: press/release, автоповтор, отсутствие двойной вставки.
- Кириллица, многострочный текст, специальные символы в браузере, редакторе и терминале.
- Все семейства моделей, восстановление после перезапуска, трей и автозапуск.
- Подписанное обновление между двумя тестовыми версиями для `.deb`, `.AppImage` и RPM.
