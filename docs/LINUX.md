# Linux x64: подготовка и проверка

Код поддержки Linux и ручная сборка GitHub Actions подготовлены. Реальная Linux-сборка и проверка микрофона на рабочем столе ещё не выполнены. Не объявлять Linux проверенной платформой и не публиковать пакеты до этих проверок.

## Первый вариант поддержки

| Возможность | X11 | Wayland |
| --- | --- | --- |
| Запись кнопкой, локальные модели, история, автозамены | Подготовлено | Подготовлено |
| Глобальная горячая клавиша и удержание для записи | Подготовлено | Недоступно |
| Вставка в другие приложения | Через xdotool | Копирование для ручной вставки |
| Буфер обмена | Через Tauri | Через wl-clipboard |
| Временное отключение системного звука | Недоступно | Недоступно |

В Wayland интерфейс объясняет ограничения и отключает неподдерживаемые настройки. Установка xdotool в Wayland не включает ввод в нативные Wayland-приложения. В GNOME для отображения значка в трее может потребоваться расширение AppIndicator.

## Сборка без установки Linux на Windows

Проверочная сборка запускается при отправке разрешённых изменений в тестовую ветку `codex/linux-0.3.0`. Также предусмотрен **Actions → Linux x64 build → Run workflow**, когда workflow доступен в основной ветке. Workflow имеет доступ `contents: read`, не создаёт коммиты, теги или релизы. Результат — архив артефактов с `.deb` и `.AppImage`; это проверочные пакеты без подписи обновлений.

Сборка использует Ubuntu 22.04 x64, Node.js 24.18.0 и Rust. Whisper.cpp 1.8.3 собирается из архива с закреплённым SHA-256. CPU-бэкенды выбираются во время выполнения; оптимизация только под процессор CI отключена. Приватный Node и нативные ONNX/sherpa-библиотеки Linux входят в пакет. Windows-ресурсы в Linux-пакет не попадают.

В CI предусмотрены проверка зависимостей исполняемых файлов, пробное распознавание тремя движками и ввод текста в отдельное X11-окно. Это не заменяет проверку микрофона, рабочего стола и установки пакета.

## Локальная сборка на Ubuntu 22.04 / Debian

Системные зависимости приведены в [workflow](../.github/workflows/linux-build.yml). Нужны также Node.js 24.18.0 и Rust. Использовать отдельную Linux-копию проекта; не делить `node_modules` или Rust `target` с Windows.

```sh
npm ci
npm run dist:linux:unsigned
```

Проект отключает скачивание необязательных CUDA-компонентов ONNX Runtime: используются CPU-библиотеки из npm-пакета. В CI это также задано переменной `ONNXRUNTIME_NODE_INSTALL=skip`.

Пакеты находятся в `src-tauri/target/release/bundle/deb` и `src-tauri/target/release/bundle/appimage`. Служба Linux собирается отдельно в `dist/desktop-linux`. Исходники и промежуточная сборка Whisper хранятся в игнорируемой `.tmp/whisper-linux-1.8.3`.

Для AppImage установить xdotool, wl-clipboard и необходимые компоненты GStreamer через менеджер пакетов дистрибутива. Для `.deb` зависимости объявлены в пакете. AppImage запускать из постоянной папки пользователя; на системах без FUSE можно использовать поддерживаемый AppImage режим извлечения. Не запускать Vokeyra от root.

## Данные и обновления

Данные по умолчанию находятся в `$XDG_DATA_HOME/Vokeyra` или `~/.local/share/Vokeyra`. Настройки, модели и история не записываются в системную папку установки. Автозапуск управляется Tauri в пользовательском сеансе; тестовые и debug-сборки его не меняют.

Для релизной сборки использовать `npm run dist:linux` с тем же ключом Tauri updater, что у Windows. Ключ не передаётся в проверочный workflow. На выходе появится `latest-linux-x64.json` с отдельными целями AppImage и Debian. Объединить его с Windows-манифестом перед публикацией:

```sh
node scripts/merge-update-manifests.mjs latest.json latest-win32-x64.json latest-linux-x64.json
```

Объединение отклоняет разные версии и конфликтующие цели. В одном релизе публикуются окончательные пакеты, их `.sig` и общий `latest.json`. Установленное `.deb`-приложение при обновлении может запросить системное разрешение на установку; AppImage обновляется в доступной для записи папке пользователя.

## Что проверить до релиза

- Установка и повторный запуск `.deb` и `.AppImage` на настоящем рабочем столе.
- Доступ к микрофону и запись с несколькими устройствами; прослушивание истории.
- X11: горячая клавиша, удержание, вставка кириллицы, восстановление буфера, Ctrl+Shift+V в терминале.
- Wayland: запуск без XWayland, запись кнопкой и ручная вставка из буфера.
- Все семейства моделей, восстановление данных после перезапуска, трей и автозапуск.
- Подписанное обновление между двумя тестовыми версиями отдельно для `.deb` и `.AppImage`.
